OpenBench Demo 1 cheat sheet

Every password is demo. Lines in italics are things to say. Lines in blue are what you should see.

Before the grader arrives

  1. Start Docker.
  2. For a clean database: docker compose down
  3. Start the app: mvn spring-boot:run -Dspring-boot.run.profiles=demo
  4. Open http://localhost:8080 in the browser.
  5. Open a second tab on the GitHub repo, and a terminal in the repo folder.

1. Intro ~1 min

  • "OpenBench is an internal marketplace. A team's Manager asks for people, rooms, and GPU time in one Request, and pays in credits."
  • "Demo 1 covers rooms and GPUs end to end. Lending people comes next."
  • Stack: Spring Boot, PostgreSQL, React. One app, one database.

2. Live demo ~5 min · 40%

Inventory

  1. Log in as dave (Resource Owner).
  2. Click Inventory. 3 types: Meeting room, Confocal microscope, GPU. The GPU pool is two nodes of 8 = 16 units.
  3. Filter by type to show the filter works.
  4. Click Sign out.
  5. Log in as carol (Administrator) and click Resource Types. "New resource types are data. No code change needed."
  6. Click Sign out.

A Request that succeeds

  1. Log in as alice (Platform Manager, 5,000 credits).
  2. Click Requests, then New Request.
  3. Add a line: Meeting room, Specific Resource Room A, 1, Tue 27 Oct 14:00 to 16:00. Click Add line. Quote 30.00
  4. Add a line: GPU, 4 units, Tue 27 Oct 09:00 to Thu 29 Oct 09:00. Click Add line. Quote 1,120.00. Total 1,150.00 of 5,000.00.
  5. Click Submit. State: Allocated. Room A is assigned.
  6. Click Statement. Grants 5,000. Charges 1,150. Available 3,850.
  7. Click Sign out.

A Request that has to wait

  1. Log in as bob (Research Manager, 600 credits).
  2. Requests, then New Request. Add Room A, Tue 27 Oct 15:00 to 17:00. Add GPU, 10 units, Tue 27 Oct 10:00 to 14:00.
  3. Click Submit. State: Waiting. Room A: NO_FREE_INSTANCE, Position 1. GPU: QUOTA_EXCEEDED, Position 1. "Room A is taken by alice, and Research may only hold 8 GPUs at once."

A Request that is too expensive

  1. New Request. All on Tue 27 Oct: Confocal microscope 09:00 to 17:00, Room B 09:00 to 17:00, GPU 1 unit 09:00 to 10:00.
  2. Click Submit. Refused: short by 7.50 credits (needs 607.50, has 600.00).

Withdraw

  1. Go back to Requests and open bob's Waiting Request.
  2. Click Withdraw. State: Withdrawn. The Position column is now blank.

If the app breaks: run mvn test -Dtest=SubmitEndToEndTest. It runs this same story against the database.

3. How much is done ~1 min · 40%

  • 15 of 41 requirements done (37%), 7 more partly built. Target was about 30%.
  • Done: Inventory, Drafts and Quotes, Submit, room and GPU allocation, Waitlist, credit Statement.
  • Not yet: lending people, dashboard, refunds, priority bumping.

4. Version control ~1 min · 15%

  1. Show the GitHub tab, or run git log --graph --oneline.
  2. "Each feature was built on its own branch and merged into main. There are 7 branches and 53 commits."
  3. "Every branch includes its own tests."
  4. "The spec lives in a separate repo, swe_csds393."

5. Testing ~1 min · 15%

  1. In the terminal, run mvn verify (or show the last run).
  2. "258 JUnit tests on the back end, 68 Vitest tests on the front end. All pass."
  3. "Database tests run on a real PostgreSQL 16 in Testcontainers."
  4. "We test the race for the last room: two people submit at once, and only one gets it."
  5. "An ArchUnit test fails the build if modules break the layer rules."

6. Next steps ~1 min · 10%

  • Increment 2: lending people. Profiles, a Shortlist of candidates, manager approvals, Loans.
  • Increment 3: refunds, priority bumping, suggestions, dashboard, settings screens.
  • Challenges: time-based rules (approval deadlines, month rollover) and keeping locks in order.
  • Process: add CI on GitHub, merge through pull requests with reviews.
