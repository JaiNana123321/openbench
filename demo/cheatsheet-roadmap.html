Increment 2: lending people

"Next we build the third Allocation Class, Matched: lending a person from one team to another."

  • Profiles: Members record their skills and availability.
  • Shortlist: for a skill request, a list of matching people, least-lent first.
  • Approvals: the person's own Manager approves or refuses. A refusal can be replaced. No answer escalates to the Capacity Planner.
  • Pending and Holds: while waiting for approval, the room and GPUs are held but not charged, for a limited time (the Objection Window).
  • Loans and Earnings: once approved, the person is on Loan and the lending team earns credits.
  • Re-check Waiting Requests whenever capacity frees up.
  • Goal: an end-to-end test of one Request asking for a person, a room and GPUs.

Increment 3: release, priority, oversight

  • Release a booking early, with refunds by how far ahead it is.
  • Priority lines that can bump standard ones.
  • Suggestions: Members propose lines to their Manager.
  • Scheduled jobs: month rollover and approval deadlines.
  • Showback dashboard, settings screens, and adding members.
  • Stretch only after that: GPU tiers, usage records, demand surcharge.

Challenges to mention

  • Time-based rules. "Approval deadlines and month rollover depend on the clock. We'll test them by moving a fake clock forward."
  • Lock order. "Loans add more locks to a submit. We have to keep taking them in the same order to avoid deadlocks."
  • Front end and API drift. "More screens means more endpoints. Generating TypeScript types from the API makes a mismatch fail the build."
  • Scope. "Four students, one semester. Release 1 is fixed, and stretch features only start once it works end to end."

Process changes

  • GitHub Actions runs mvn verify and npm test on every push and pull request.
  • Every merge goes through a pull request reviewed by another teammate.
  • Vitest runs inside mvn verify, so one command checks everything.
  • Each requirement becomes a tracked issue with an owner.

Closing line

"In Demo 2, alice will ask for a person, a room and GPUs in one Request. Bob's team lends the person and earns credits for it. Questions?"

If the grader asks

  • "What's the riskiest part?" The approval flow, because it mixes timing (deadlines), Holds on other resources, and a second Manager's decision.
  • "How will you know you're on track?" The end-to-end test of the three-line Request. When it passes, Increment 2 is done.
  • "What if you run out of time?" Stretch features are optional extension points, so dropping them doesn't break anything.
